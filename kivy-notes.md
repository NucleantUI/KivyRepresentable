# Kivy notes

Running notes for the KivyRepresentable experiment. See `plan.md` for the goal,
`progress.md` for the graphics checklist.

## Shape of it

- A Swift app is the host. Python is started from inside it (via
  PySwiftKit) before the Kivy window group comes up — Python never launches
  the app.
- One shared C api, linked by both sides:
  - Swift side (KivyRepresentable): its own shader node, built on
    NucleantVulkan only, the way NucleantSkia ships `SkiaShaderNode`
    (`SkiaShaderNode<ContainerNode>: VulkanSkiaRenderNode: VulkanRenderNode`
    + a `VulkanRenderEngine` extension that makes the engine-owned VkImage).
    It owns the shared VkImage and implements the GL table into it.
  - The view part lives here too, built on NucleantUI as a dependency.
    Build with `swift build --target KivyRepresentable` (and
    `--target CKivyNUI` for the dylib), not a plain `swift build`.
  - **NucleantUI itself is not changed.** Use it as it is; nothing added to
    it. How the node gets hooked into NucleantUI's own rendering is decided
    later (maybe a NucleantUI branch). If something seems to need a
    NucleantUI change, stop and say so; don't make it.
  - Kivy/Cython side: links the same C api and renders into that image.
- Kivy is a singleton (one App, one Window), so one shared shader node is
  enough.

## Ground rules

- **Replace the GPU layer, not Kivy.** Canvas, instructions, vertex/context
  instructions, Fbo, Texture etc. are *not* rewritten. They keep issuing the
  same calls as today; the layer under them (the `cgl` backend / shared C api)
  is what changes, and it renders into the shared image. The more Kivy files
  we touch, the more this experiment fails.
- **What we do change:** the window provider (`_nui`), the clock (ticked by
  DisplaySync), the providers that depend on SDL (text, image, clipboard),
  and provider selection/config so `nui` can be picked. Prefer adding new
  files over editing existing ones.
- **Kivy's orientation is respected: origin bottom-left, y up.** The host is
  top-left, y down. The conversion happens on *our* side, at the boundary,
  never inside Kivy:
  - Input (mouse, touch, scroll): forwarded **unflipped**, top-left, the way
    SDL delivered them. Kivy's own code does the flip, and must keep doing
    it: `window_sdl2.py` `_fix_mouse_pos` (`system_size[1] - 1 - y`), the
    mouse provider's `ny = 1.0 - ny` (`kivy/input/providers/mouse.py`), and
    the SDL touch provider's `y = 1 - y`. Flipping before Kivy would flip
    twice. So "on our side" means: match SDL's coordinates exactly
    (window points, top-left; touches normalized 0…1, top-left).
  - Output: Kivy keeps rendering with its own projection. If the shared image
    comes out upside down in Vulkan, the shader node fixes it when it samples
    the image (flip v). Kivy's matrices are not touched.

## Shared C api — `dependencies/CKivyNUI/include/kivy_nui.h`

- Built by the Swift package (`Package.swift`) as the dynamic library
  `libCKivyNUI.dylib`. The Swift host and Kivy's Cython extensions both
  link that one library, so there is one copy of its state in the process.
- Each side registers a table with it: the host (`kivy_nui_set_host`) before
  Python starts, Kivy (`kivy_nui_set_kivy`) from `_window_nui.pyx`. Exported
  `kivy_nui_*` functions forward to the other side's table.
- GPU (`kivy_nui_gl.h`, generated by `generate_kivy_nui_gl.py` from
  `kivy2x`): Kivy's whole GPU dependency is the `GLES2_Context` table in
  `kivy/graphics/cgl.pxd`, 129 functions. `KivyNUIGL` is that table member
  for member (same names, same signatures, our own type names so it can be
  included next to system GL headers), plus the 299 `GL_*` constants
  cgl.pxd declares as `KIVY_NUI_GL_*`. The host implements the table on
  Vulkan and registers it (`KivyNUIHost.gl`). `cgl_nui.pyx` copies
  `kivy_nui_gl()` into Kivy's table, the way `cgl_angle.pyx` fills it from
  `eglGetProcAddress`. Framebuffer 0 = the shared image. The VkImage never
  shows up in the api.
  - Kivy's shaders: GLSL with no `#version`, `#ifdef GL_ES` precision
    header (`kivy/data/glsl/header.vs/.fs`). Attribute locations are read
    after linking (`glGetAttribLocation`, `shader.pyx:533`).
  - `cgl.pxd` has `GL_ANT_COLOR` / `GL_ANT_ALPHA` (+ `ONE_MINUS_`): a typo
    for `GL_CONSTANT_*` in Kivy itself, no value anywhere, unused. Skipped.
- Input: queued by the host (`kivy_nui_push_event`), drained by Kivy with
  `kivy_nui_poll_event`, the same pull model as `_window_sdl2.pyx` `poll()`.
  So `window_nui.py`'s event handling can stay close to `window_sdl2.py`'s.
  Event types mirror SDL's `poll()` actions (no joysticks); key codes,
  scancodes, `KMOD_*` bits and mouse button numbers are SDL2's, so Kivy's key
  mapping stays as is.
- Clock: the host's DisplaySync callback calls `kivy_nui_tick(dt)` (dt =
  seconds since the previous tick, what `DisplaySync.newCallback` gives).
  Kivy's tick = one pass of its old main loop: poll events, clock, draw,
  `kivy_nui_present` (= `Window.flip`).
- Window commands from Kivy so far: title, system cursor (Kivy's 12 names),
  cursor visibility, show/hide keyboard, request close. Clipboard is its own
  provider, not here yet.
- GL context: Kivy's window asks the host for one before its first GL
  call (`kivy_nui_create_gl_context`) and drops it on close
  (`kivy_nui_destroy_gl_context`) — EGL's role for ANGLE. The host makes
  its GL then, framebuffer 0 at the window's pixel size.
- Status: headers + `kivy_nui.c` (tables, forwarding, event queue);
  `Tests/CKivyNUITests` covers them (`swift test --filter KivyNUITests`).

## GLES2 on Vulkan — `Sources/KivyRepresentable/GL/`

What ANGLE is to Kivy on Metal. `KivyGL.table` is the `KivyNUIGL` the host
registers; every member forwards to `KivyGL.current` (Kivy has one context).

- Recording: one command buffer per Kivy frame, begun by the first call that
  needs the GPU, submitted and waited for at `present` (or glReadPixels /
  glFinish). Render passes open lazily on the bound framebuffer and close
  when it changes or a transfer is needed; barriers come from each image's
  tracked layout.
- Buffers live on the CPU; each draw copies what it uses into a per-frame
  streaming buffer (cached per buffer version), so a draw sees the data as
  it was when issued, GL's rule.
- Every color image is RGBA8; RGB, BGRA, luminance, alpha etc. are
  converted on upload. Depth/stencil renderbuffers are one combined format
  (D24S8 or D32S8, whichever the device attaches).
- Shaders (`GLSLTranslator.swift`): GLSL ES 1.00 → Vulkan GLSL 450, then
  shaderc (NucleantShader). attribute/varying get locations (varyings by
  name, shared by both stages), samplers get bindings, plain uniforms go into
  one std140 block laid out the same in both stages; glUniform* writes its
  bytes. The vertex `main` is wrapped to map GL's clip z (-w..w) to Vulkan's
  (0..w).
- No y flip anywhere inside: GL's window row 0 and Vulkan's framebuffer row
  0 are both the first row in memory, so rendering is in GL's memory order
  (what Fbo textures and glReadPixels expect). `present` blits framebuffer 0
  into the shader node's image flipped, for the composite. Front face is
  inverted (Vulkan's signed-area formula has the opposite sign).
- GL_TRIANGLE_FAN / GL_LINE_LOOP (Kivy's Mesh, Line) become triangle lists /
  line strips with generated indices: MoltenVK has no fans, Vulkan no loops.
  16-bit indices stay below 0xFFFF: Metal always restarts strips there.
- Caches are keyed by serial numbers, never object addresses: a VBO Kivy
  deletes and recreates can land at the same address.
- `GL_OES_standard_derivatives` is advertised: Vulkan GLSL has derivatives
  built in, so the translator drops its `#extension` line (GLSL won't let
  `GL_` names be defined, so `#ifdef GL_OES_standard_derivatives` is false).
- Samplers without mipmap filtering cap the LOD at 0.25 with nearest mip
  selection, not 0: Vulkan picks min vs mag filter after the clamp, so a cap
  of 0 always magnifies and GL_NEAREST minification came out linear. 0.25
  still minifies and rounds to level 0 (ANGLE's choice).
- Skia into textures (`KivyGL+Skia.swift`): `gl.drawWithSkia(texture:)`
  wraps a GL texture's own VkImage as a NucleantSkia `SkiaSurface` (kept on
  the image, dropped before it) and hands the `SkCanvas` over: Skia draws
  straight into what Kivy samples, no CPU pixels, NucleantSkia unchanged.
  The Ganesh context is made on first use, on the GL's device and queue
  (the engine's `makeSkiaContext`, or one over the headless instance). Kivy's
  recorded work is submitted first; Skia flushes to COLOR_ATTACHMENT and the
  frame's own barrier takes it from there. The canvas is the texture's rows
  first row at the top, as Kivy's image data: a texture Kivy flips
  (`flip_vertical`) shows it upright. Single-level textures only (Skia wraps
  one level). Kivy redraws only when asked, so after drawing the canvas
  showing the texture needs `ask_update()`. `fillWithSkia` draws a whole
  texture anew from transparent (the providers): storage made at the given
  size if Kivy hasn't made it yet, a mipmapped texture remade with one
  level for Skia and its mipmaps made again after (`makeMipmaps(of:)`).
- Not done (left nil in the table): compressed textures, glCopyTex*,
  glShaderBinary; cube maps; client-side vertex/index arrays (Kivy always
  uses buffers).

## Host — `KivyHost`, `KivyNUILibrary`

- `KivyHost` registers the host table, makes `KivyGL` when Kivy asks,
  presents, forwards ticks/events, resizes framebuffer 0.
- It calls the C api through `KivyNUILibrary` — `dlopen` of the shared
  `libCKivyNUI` — never the copy compiled into this module: Kivy's
  extensions link the dylib, and a host registered with a different copy is
  one Kivy never sees.
- `KivyProviders` (owned by the host): what the `nui` text and image
  providers call through the host table (`text_extents`, `font_metrics`,
  `draw_text`, `image_size`, `draw_image`, `image_pixels`): typefaces by
  font file, SkFont from Kivy's options, runs drawn into the texture with
  `KivyGL.fillWithSkia`; images decoded by SkCodec, or parsed as SVG
  (`SkSVGDOM`) when no codec reads them, and drawn there.
- `libKivyNUIHeadless` (product `KivyNUIHeadless`): a windowless host on its
  own Vulkan device, for a process that already runs Python;
  `kivy_nui_headless_start/read/stop`, and
  `kivy_nui_headless_skia_pattern` (Skia draws a known picture into a Kivy
  texture, for the render test).

## In an app — `KivyApp`, `KivyWindowGroup`, `KivyLauncher`

    @main
    struct MyApp: KivyApp {
        var site_packages: String { Bundle.module.resourceURL!.appendingPathComponent("site_packages").path }

        var body: some Scene {
            KivyWindowGroup("Kivy", module: "myapp")
        }
    }

- Python belongs to the app, launched once: `KivyApp.main()` (wins over
  `NucleantApp.main()` for a `KivyApp`) makes the app, launches
  `KivyLauncher(sitePackages: [app.site_packages])` — `preLaunch` →
  `initPython` → `onLaunch` (releases the GIL) — then runs that same app
  through NucleantUI's public `AppRuntime` (`setup`, `run`), as
  `NucleantApp.main()` does. NucleantUI knows nothing of Python. The
  launcher reaches the window's view as `@Environment(\.kivyLauncher)` (in
  `KivyView`; the key's default is the one `main` launched, outside a
  `KivyApp` one with `isLaunched == false`).
- `KivyWindowGroup(title, module:)` only picks the module. No window
  singleton: each group has its own session, window, slot and host. Its
  root `KivyView` draws nothing, forwards press/drag/release as SDL mouse
  events (`DragGesture(minimumDistance: 0)`) and, on appear, starts the
  session: adds a `.kivy` slot to the window's engine (public
  `renderEngine`), imports `kivy.graphics.ngl_backend.ngl_nui` in the app's
  Python (which loads the libCKivyNUI Kivy links), registers the host with
  *that* library (`KivyNUILibrary.loadedByKivy()`), then runs the module
  with `runpy` as `__main__` (`launcher.runModule`, taking the GIL for the
  call). `App.run()` returns.
- NucleantUI's `EnvironmentValues` returns nil for an optional key with a
  non-nil default (`storage[key] as? Value?` of a missing entry is
  `.some(nil)`), so `kivyLauncher` is non-optional.
- Ticking: the engine's `onUpdate` (start of every `drawFrame`) ticks Kivy,
  which presents into the slot before the frame composites it. The `.kivy`
  slot keeps `needsRender` set, so the engine draws every display frame.
- Resize: each frame compares `win_rect` (pixels); on a change the slot's
  image is replaced (`invalidateComposite`, old one freed after in-flight
  frames), framebuffer 0 resized, Kivy told WINDOW_RESIZED. Points come from
  `@Environment(\.displayScale)`.
- `KivyLauncher`: a class shaped as kivy-school/KivyLauncher (its code,
  not the package): `env` (its `Environment`, env vars by name),
  `preLaunch` → `initPython` → `onLaunch`, then `runModule` per window.
  PythonLauncher's isolated init — home = the prefix of the
  linked Python (found through `dladdr`, LoadedLibraries+Apple.swift),
  stdlib + lib-dynload on the path, `site_import = 0` (python.org's own
  site-packages can hold another Kivy), then `site.addsitedir` per
  `sitePackages`. Sets `KIVY_WINDOW=nui`, `KIVY_GL_BACKEND=nui`,
  `KIVY_NO_ARGS=1` unless already set (`launcher.env.X = …` before launch).
- Python comes from PySwiftKit's CPython package (local checkouts in
  Package.swift), normal mode: python.org's Python.framework 3.13. What
  links it needs `-F/Library/Frameworks` (tests, headless lib, the app).
- `img_nui` is ignored in the app: Kivy picks image providers at
  `import kivy`, which the `ngl_nui` import does before the host registers
  (`kivy_nui_has_text_and_images()` is still false then). Text is picked
  later and gets `nui`.
- Not yet: pointer motion without a button (NucleantUI views only see the
  pointer during a drag — Kivy's hover needs plain motion events), scroll,
  keyboard, window title from Kivy (`HostingWindow.title` is internal).

## Kivy side (in `kivy2x`)

New files:
- `kivy/lib/kivy_nui.pxi`: Cython declarations of `kivy_nui.h`, included like
  `lib/sdl2.pxi`. `KivyNUIGL` members are declared `void *`; cgl_nui casts
  each to Kivy's own pointer type.
- `kivy/graphics/ngl_backend/ngl_nui.pyx`: `NGLNUI`, the GL context —
  `create_context` / `swap_buffers` / `destroy_context`, as `EGLANGLE` in
  `egl_backend/`. `_window_nui.pyx` makes it before Kivy's first GL call
  (skipped for the `mock` backend) and swaps through it on flip.
- `kivy/graphics/cgl_backend/cgl_nui.pyx`: made from `cgl_angle.pyx`, each
  `eglGetProcAddress("glX")` → `gl.glX` from `kivy_nui_gl()`.
- `kivy/core/window/_window_nui.pyx`: `_WindowNUIStorage`; `poll()` returns
  `_window_sdl2.pyx`'s tuples (wheel and dropbegin carry the cursor position
  SDL's window queried separately). Registers the tick (`set_tick`).
- `kivy/core/window/window_nui.py`: `WindowNUI`, WindowSDL's event handling
  and key maps; the host's tick runs one pass of `EventLoop.mainloop`
  (`EventLoop.idle()` + `mainloop()`); `_finish` does what `runTouchApp` /
  `App.run` did after the loop, then `request_close`. Refuses to start
  without a host, so `core_select_lib` falls through.

Changed in Kivy (originals of replaced functions kept under a `_` name):
- `kivy/clock.py`: `ClockBaseBehavior.idle` no longer sleeps for `maxfps`;
  original is `_idle`. (Default clock only; the interrupt/free clocks keep
  their own `idle`.) This changes the default clock for SDL builds too.
- `kivy/base.py`: `runTouchApp` returns without looping when the window has
  `ticked_by_host`; original is `_runTouchApp`.
- `kivy/app.py`: `App.run` returns without `_stop()` in that case; original
  is `App._run`.
- `kivy/lang/builder.pyx`: `_new_ids` typed `object` instead of `dict`.
  `root.ids` is an `ObservableDict`, a dict subclass, and the Cython 3 build
  rejects it ("Expected dict, got ObservableDict") as soon as a kv file
  uses `ids`. A bug in kivy2x itself, not nui-specific.
- Kivy bugs found by `test_render_nui.py`, every backend has them:
  - `graphics/instructions.pyx` `Callback(reset_context=True)` walked
    `ctx.lr_shader` (programs waiting to be deleted) to forget each shader's
    bound vertex format, so it forgot nothing: the reset disabled the vertex
    attributes and Kivy never enabled them again, and the next draw had no
    vertices. `Context` now keeps `l_shader` (weak refs, as `l_texture`),
    `Shader.__init__` registers there (`register_shader`), and the reset
    walks it.
  - `graphics/context_instructions.pyx`: `LoadIdentity` and
    `ApplyContextMatrix` never called `ContextInstruction.__init__`, so a
    `with canvas:` block never added them. They do now.
  - `graphics/svg.pyx` `push_line_mesh`: a gradient stroke went into the
    float `g` (`g = self.gradients[fill]`) and raised. Svg strokes every
    filled shape with its fill, so any gradient fill hit it. Now
    `gradient = ...`, as `push_mesh` does.
  - Not fixed, worked around in the test: Svg reads gradients in user space
    only and skips a coordinate of 0 (`if v:`).
- `graphics/vertex_instructions.pyx` `Ellipse` (so every circle in Kivy) is
  drawn by a shader of its own instead of a CPU-built triangle fan of one
  segment per 2°: one quad (a unit past the box, for the edge), and the
  fragment shader's coverage is its distance from the edge in pixels
  (`dFdx`/`dFdy`), so the edge is exact and antialiased at any size. Arcs
  (`angle_start`/`angle_end`) cut it with two half-planes through the
  center, antialiased the same way. Fragments with no coverage are
  discarded, so it still masks round as a stencil. The context's state
  (matrices, color, opacity) is carried to the ellipse shader for the draw,
  then the context's shader is put back. The fan stays for an explicit
  `segments` (Kivy's way of drawing polygons) and inside a RenderContext
  whose shader isn't Kivy's default (that shader fills the geometry it's
  given; `Shader.is_default()` tells). `SmoothEllipse` drops its
  AntiAliasingLine when the shader draws. The shader is made once per
  process; a GL context loss (none in nui) doesn't rebuild it.
- `graphics/vertex_instructions_line.pxi` `Line(circle=…)` /
  `Line(ellipse=…)` (and `SmoothLine`'s) are drawn by a ring shader instead
  of a polyline of one segment per 2° with its joints: one quad over the
  ring, and each fragment finds the closest point on the curve (Newton
  steps; exact for a circle) and covers by its distance to the stroke's
  edge, in pixels. Widths as the polyline had them: `width` each side, 1 is
  a one-pixel line at any scale, SmoothLine solid to `width - 1` and fading
  over the overdraw width. An arc ends on the normal through its end point
  (where the polyline's last segment ended): "past the end" is the closest
  point being outside the arc, and only near the end point does the
  distance to that normal give the flat end its antialiased edge (a flat
  ellipse comes back around behind it). Caps none/square/round past it.
  `close` adds the chord, or the two radii for `close_mode='center-connected'`
  (ellipses only, as Kivy), joined round. Dashes (width 1 only, as Kivy)
  are measured along that path (Simpson's rule for an ellipse's arc
  length) through the dash texture Kivy makes, now `build_dash_texture()`.
  No stencil pass at alpha < 1: the ring has no overlaps. `points`,
  `circle`, `ellipse` are made when read (`refresh_points()`). The
  polyline stays for an explicit `segments`, a closed arc with joints other
  than round (or center-connected without round caps), and a RenderContext
  with its own shader.
- `kivy/lib/kivy_nui.py`: ctypes on `kivy_nui.h`'s text and image calls
  (no Cython). Opens the shared library through `ngl_nui`'s file without
  importing it (a lookup on that handle searches its dependencies, so it is
  the library the host registered with); ImportError unless
  `kivy_nui_has_text_and_images()`, so providers fall through.
- `kivy/core/text/text_nui.py`: `LabelNUI`. `get_extents` / ascent /
  descent from the host; `_render_text` collects runs, `_render_end` has the
  host clear the label's texture and draw them (Skia, straight into its
  image) and returns a 1x1 ImageData, which `_render_real` doesn't blit.
  Laid out as the SDL2 provider: line box from (x, y), baseline an ascent
  down, outline grows extents by its width each side, descent negative.
  Font file, size, hinting, blended, underline, strikethrough, outline,
  colors; no kerning (Skia's simple text isn't shaped).
- `kivy/core/image/img_nui.py`: `ImageLoaderNUI` (png, jpg, webp, bmp, ico,
  wbmp, and svg through NucleantSkia's `SkSVGDOM`, sized by the root's
  width/height or else its viewBox, as SDL_image did; GIF stays with
  loaders that read every frame). `load` reads the
  file's bytes (or `rawdata`) and asks the host for the size; `populate`
  makes the texture with a fill callback, as a label's, and the host
  decodes and draws into it when Kivy first binds it. With `keep_data` the
  host decodes to bytes instead and Kivy uploads them as usual.
- One-word additions: `'nui'` in `kivy_options['window']`
  (`kivy/__init__.py`), the recognized backends in `cgl_init`
  (`graphics/cgl.pyx`), and `('nui', 'window_nui', 'WindowNUI')` first in
  `window_impl` when `USE_NUI` (`core/window/__init__.py`); `'nui'` first
  in `kivy_options['text']` / `['image']` and in `label_libs` /
  `image_libs` when `USE_NUI` (`core/text/__init__.py`,
  `core/image/__init__.py`).
- `setup.py`: `c_options['use_nui']` (`USE_NUI=1`), `determine_nui_flags()`
  (`KIVY_NUI_INCLUDE_DIR` / `KIVY_NUI_LIB_DIR`, default: this package's
  `dependencies/CKivyNUI/include` and `.build/debug`), and the two
  extensions. cgl_nui uses `gl_flags_base`: no system GL is linked.

Build (Python 3.13, uv):

    swift build --product CKivyNUI
    cd kivy2x
    USE_NUI=1 USE_SDL2=0 USE_GSTREAMER=0 USE_PANGOFT2=0 \
        uv build --wheel --python 3.13 --out-dir wheelhouse

- `USE_NUI=1` builds `cgl_nui`, `ngl_nui` and `_window_nui` against
  `dependencies/CKivyNUI/include` and `.build/debug/libCKivyNUI.dylib`
  (`KIVY_NUI_INCLUDE_DIR` / `KIVY_NUI_LIB_DIR` override). `USE_SDL2=0` etc.:
  nothing of SDL, GStreamer or Pango is needed.
- uv's build env installs Kivy's pinned build deps (Cython <=3.0.11; 3.2
  fails on `long` in Kivy's own .pyx files). uv's own CPython 3.13 is
  x86_64 on this Mac, matching the dylib; no ARCHFLAGS needed.
- The modules link `@rpath/libCKivyNUI.dylib` with the rpath pointing at
  this checkout's `.build/debug`: the wheel works on this machine only, for
  now. Bundling the dylib (cibuildwheel/delocate) is for later — the host
  then has to `dlopen` that copy (`KivyNUILibrary.load(path:)`).

## Where things live in `kivy2x`

- Window provider (SDL today): `kivy/core/window/window_sdl2.py`,
  `kivy/core/window/_window_sdl2.pyx` → new `window_nui.py` / `_window_nui.pyx`.
- GL function table: `kivy/graphics/cgl.pyx` picks a backend from
  `kivy/graphics/cgl_backend/` (`cgl_gl`, `cgl_glew`, `cgl_sdl2`, `cgl_angle`,
  `cgl_mock`, `cgl_debug`). A `cgl_nui` backend is the natural slot for ours.
- ANGLE reference for "kivy draws into something it doesn't own":
  `kivy/graphics/egl_backend/` (`egl_angle*.pyx`, `egl_angle_metal_implem.mm`).
- Clock: `kivy/_clock.pyx` — `CyClockBase.tick(curtime)`; to be driven by a
  NucleantSync DisplaySync callback instead of Kivy's own loop.
